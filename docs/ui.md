# 画面のレイアウト方針

結果ページの 2 カラムについて、**なぜそうしたか**の記録です。利用者向けの説明は
[README](../README.md#画面) にあります。

**具体的な数値（サイドバー幅・ブレークポイント）はここに書きません。** 二重管理になって
片方だけ古くなるためです。数値は `cmd/seekx/static/style.css` のコメントが持ち、
`cmd/seekx/render_test.go` が固定しています。

## サイドバーの並びは「注意 → 操作 → 参照」

上から警告・部分エラー（条件付き）、列数の切り替えと絞り込み、生成クエリと件数・コスト。

貼り付くサイドバーでは、繰り返し触るものが上に来る必要があります。参照情報を先に置くと、
操作部に届くまでスクロールが要り、`max-height` で内部スクロールが出たときに隠れるのも
操作部の側になります。警告を操作より上に置いたのは、注意を要する例外だからです。条件付きなので
普段は場所を取りません。

`TestResultsSidebarLayout` / `TestSidebarPutsNoticesFirst` が固定しています。

## フォロワー一覧も同じ 2 カラム

フォロワー一覧（`followers.html`）は、`FollowersPage.PageID` が結果ページと同じ `results` を返すので、
同じ CSS が当たります。カードを並べるグリッドと列数の閾値も、投稿の一覧と同じ `.post-list` を使います。
専用のレイアウトを持たないのは、このファイルに書いた判断（サイドバーの位置・列数・狭い画面での積み方）を
そのまま引き継ぐためです。

サイドバーの並びも同じ「注意 → 操作 → 参照」です。

- 注意: 警告（指標を取得できなかった人数）と部分エラー（どちらも条件付き）
- 操作: 列数の切り替えと CSV 保存（絞り込みはありません）
- 参照: 対象（ユーザー名と ID）・表示中の人数・今回のコスト・レートリミット

対象にユーザー名と並べて ID も出すのは、取得は ID で行い、ユーザー名は URL から来る表示用の値で
食い違い得るためです。

一覧の id は投稿の一覧（`#post-list`）と分けて `#user-list` にしています。列数の切り替えとヘッダ高さの
実測はどちらの一覧にも効かせますが、絞り込みは投稿のカードを前提にしているので、ユーザーカードには
向けません。ユーザーカードは投稿カードの頭の部分（アバター・名前・X ロゴ）と指標のクラスを共用し、
カード自体は margin を持ちません（間隔は、一覧ではグリッドの gap、見積り画面では外側の `.user-target` が
持ちます）。

`TestFollowersSidebarLayout` が並びと置き場所を、`TestStyleSheetInvariants` がユーザーカードの CSS を
固定しています。

## 列数を切り替えてもサイドバーは動かない

`main` / `.site-header` / `.banner` / `.site-footer` はページ幅で中央寄せされているので、
ページ幅が列数で変わると左端が横に飛びます。**結果ページのページ幅は列数に依らない値
（3 列時の幅）で固定**し、列数で変わるのはカード領域の幅だけにしてあります。余りはカード列の
左右へ均等に配ります。

余りを配るのに `justify-self` は使えません。グリッド項目の幅が `fit-content` になり、
**カードの中身次第で列幅が変わってしまう**ためです。auto マージンなら幅は
`min(トラック幅, max-width)` で決まり、余りだけが配られます。

`TestSidebarStaysPutAcrossColumnCounts` が固定しています。

## 金額が発生するリンクはサイドバーに置かない

ページング（`次の 100 件を取得（+$0.50）`）と再見積りはカード列に残しています。サイドバーは
常時見える位置なので、置くと誤クリックを招きます。カード以外をサイドバーへ移す変更（#17）でも
この方針は反転させていません。

フォロワー一覧も同じで、前後のページの取得（`次の 100 人を取得（+$1.00）`・`前の 100 人を取得（+$1.00）`）と
再見積り（`このアカウントを再見積り（+$0.010）`）はカード列に置いています。前のページへ戻るのも取り直しで
課金されるため、次のページと同じく金額を出します。

一方、CSV 保存はサイドバーの操作部に置いています。課金も通信も無く（API もサーバも呼ばず、埋め込み済みの
データをブラウザが保存するだけ）、このページで完結する点で絞り込みと同じだからです。操作部はフォーム要素で
囲みません。囲むと Enter や送信でこの URL を読み直し、再取得（課金）になり得るためです。

`TestResultsSidebarLayout` と `TestFollowersSidebarLayout` が、サイドバーにページングと再見積りが
入っていないことを見ています。

## 狭い画面ではサイドバーを積む

サイドバーを横に並べるのは、カード領域が読める幅を保てる画面幅からです。それより狭いときは
全幅にしてカードの上へ積み、貼り付けもやめます（固定すると投稿を読む領域が残らないため）。

**ヘッダの固定とサイドバーの横並びは閾値が違います。** ヘッダは 1 行なので狭い画面でも固定
できますが、サイドバーを横に置くとカード領域が潰れるため、より広い画面幅からになります。

列数を落とす閾値も 2 系統あります。サイドバーが積まれている間はカードが画面の全幅を使える
ので、サイドバーが占める幅を引く前の値で判断します。1 系統にまとめると、積んでいて全幅ある
のに 1 列へ落ちます。

## JavaScript の役割

2 カラムの配置そのものはサーバが出す `<html data-page="results">` に対する CSS なので、
**JS の有無に関係なく効きます。** JS が担うのは列数の保存・適用、絞り込み、ヘッダ高さの実測、
フォロワー一覧の CSV 保存（`csv.js`）の 4 つだけです。

サイドバーで `hidden` を付けるのは、JS が無いと使えない操作だけです。結果ページは操作部
（`#list-controls`）、フォロワー一覧は操作部と CSV 保存のボタン（`#csv-download`）の 2 つです。
サイドバーごと隠すと、JS 無効時に生成クエリとコスト表示（フォロワー一覧では対象・人数・コスト）まで
消えます。ボタンにも別に付けるのは、列数の切り替えは動いても保存の手段（`Blob` と Blob URL）が無い
ブラウザで、ボタンだけを出さずにおくためです。

JS が無効なときは CSV 保存のボタンが出ません。CSV のデータは HTML に埋め込まれていますが、それを
ファイルにする手段がブラウザの JS しかないためです。

`TestFollowersSidebarLayout`（`hidden` は 2 つだけ）、`TestInlineScriptInvariants`（JS の行数予算と
不変条件。`csv.js` を含む）、`TestLayoutLoadsExternalScripts`（`csv.js` は `app.js` の後、本文の末尾で読む）が
固定しています。
