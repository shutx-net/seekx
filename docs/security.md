# セキュリティ

seekx は**認証を持たないローカルサーバ**で、**課金される操作を実行できます**。この 2 つが
設計上の前提です。以下はそこから来る判断の記録です。

利用者向けの要点は [README](../README.md#安全に使うための注意) にあります。

## バインド方針

- サーバは既定で `127.0.0.1`（ループバック）にバインドします。LAN の他の端末からは
  TCP レベルで到達できません。**広く開けるほうを明示させる**ための既定です。
- **コンテナで動かす場合は `SEEKX_BIND=0.0.0.0` が必要です。**コンテナ内のループバックは
  ホストから到達できないためで、`.devcontainer/go/devcontainer.json` が `containerEnv` で
  指定しています。この場合、ネットワーク構成次第では LAN の他の端末から UI に到達できます。
  **公開ネットワークでは起動しないでください**（第三者が課金操作を実行できます）。
  ホストのファイアウォール設定に依存する前提です。
- バインドを絞ることと、下の「リクエストの境界チェック」は守る対象が違います。
  バインドは LAN からの**直接アクセス**を塞ぎ、境界チェックは**ブラウザを踏み台にした攻撃**
  （他サイトからの課金リクエスト・DNS rebinding）を塞ぎます。DNS rebinding が狙うのは
  `127.0.0.1` なので、**ループバックに絞っても境界チェックは必要**です。
- Bearer Token はサーバプロセス内にのみ保持し、HTML・ログ・エラー画面・URL には一切出力しません
  （出るのは先頭 4 文字と文字数のマスク表示のみ）。設定画面から入力する場合も同じで、
  **入力欄への prefill も含めて値を描き戻しません**。ページを読めた相手にトークンを渡さないことが、
  認証を持たないこのサーバでの前提です。

## Bearer Token の設定

**このプロジェクトの方針は「トークンを `.env` に書かず、設定画面（`/settings`）から入力する」です。**
起動後にブラウザで開き、`/settings` で入力してください。`BEARER_TOKEN` が無くても起動できます
（起動時に警告を出し、検索やフォロワー取得を実行しようとすると API を呼ばずに設定画面へ誘導します）。

設定画面から入力した値は**プロセスのメモリにのみ保持し、ディスクには書きません**。
この方針で運用する限り、**トークンはディスクに一切残りません**。`.env` に書くと、
そのファイルが存在する間ずっとトークンがディスク上に残り、`git add -f`・バックアップ・
ディレクトリ同期といった経路で漏れる余地が生まれます。

代償は、プロセスを停止すると消えるため**起動のたびに入力が必要**なことです。
これを避けたい場合に限り `.env` に `BEARER_TOKEN=...` を書けます（優先順位は
**設定画面 > `.env` / 環境変数**で、設定画面の値を削除すると `.env` の値に戻ります）。

設定画面の値を永続化しないのは、書き込み先のパーミッション・`.gitignore` の抜け・
`.env` を書き戻すときのロスト（`.env` パーサはコメントと引用符を捨てます）といった
別種のリスクを増やさないためです。トークンをディスクに置くなら、seekx が書いた
新しいファイルではなく、あなたが管理している `.env` に置くほうが扱いが明確です。

設定にまつわる扱い:

- 受け取りは **POST のみ**です。GET にすると値が URL・ブラウザ履歴・ログに残ります。
- 他サイトからの POST は下の「リクエストの境界チェック」で弾かれます。ブラウザは他サイトへの
  POST に必ず `Origin` を付けるため、Cookie を使う CSRF トークンを導入せずに済んでいます。
- トークンが変わるとセッション累計コストと月次 cap のキャッシュを捨てます。別アカウントの消費を
  1 つの累計に混ぜると、セッション累計と cap の表示がどちらのアカウントのものでもなくなるためです
  （同じ値を入れ直した場合は維持します）。
- **トークンはプロセス全体で 1 つです。**「UI から設定できる」ことはマルチユーザー対応ではありません。
  複数人が同時に開くと、後から設定した人のトークンで全員の検索・フォロワー取得が実行され、その人に課金されます。
- 入力値の正しさは確認しません（検証には API 呼び出しが必要でレートリミットを消費するため）。
  誤っている場合は検索やフォロワー取得の実行時に HTTP 401 になります（401 は課金なし）。
- フィクスチャモードではトークンを設定しても API 経路は生まれません（`Client` は HTTP クライアントを
  持たないままです）。

## リクエストの境界チェック

seekx は認証を持ちません。そのため、ブラウザを踏み台にした 2 つの経路を入口で塞いでいます
（`cmd/seekx/guard.go`）。いずれも該当したリクエストは本文を処理せず 403 を返します。

**1. 他サイト起点のリクエストを拒否します。**
課金が発生する経路は `GET /search?mode=estimate|execute`（counts の見積りと投稿の検索）と
`GET /followers?mode=estimate|execute`（ユーザー検索による見積りとフォロワー取得）で、いずれも GET
リクエストです。対策が無いと他サイトに置かれた `<img src="http://localhost:5050/search?mode=execute&…">` を
踏むだけで課金が発火します（レスポンスは同一オリジンポリシーで読めませんが、課金は成立します）。

ガードはルータ全体を包んでいるので、経路ごとの対応は要らず、新しい経路にも自動で効きます。
他サイト起点の拒否は `TestRequestGuardBlocksCrossSiteBilling`（検索の実行）と
`TestRequestGuardBlocksCrossSiteFollowers`（フォロワーの見積りと取得）が固定しています。後者を経路ごとに
分けているのは、`/followers` だけがガードの外に出る組み替えを検出するためです。

判定には `Sec-Fetch-Site` を使い、`same-origin`（アプリ内の遷移）と `none`（アドレスバー・
ブックマーク）だけを通します。ヘッダが無い場合は `Origin` にフォールバックし、どちらも
無い場合は通します（curl などブラウザ以外からの呼び出し。CSRF はブラウザを踏み台にする
攻撃なので、ヘッダを自由に作れる相手を止めても意味がありません）。

Fetch Metadata の一般的な方針は「トップレベル遷移かつ GET」なら他サイトからでも通しますが、
seekx は意図的にそこから外れています。課金経路がまさに GET のトップレベル遷移であり、
他サイトから正当にリンクされる場面が無いためです。

**2. 想定外の `Host` ヘッダを拒否します（DNS rebinding 対策）。**
攻撃者のドメインが `127.0.0.1` に解決するよう仕込まれると、攻撃者のページがこのアプリと
同一オリジンになりレスポンスまで読めてしまいます。ブラウザが送る `Host` は攻撃者の
ドメインのままなので、そこで落とします。既定の許可は `localhost` / `127.0.0.1` / `::1` で、
比較はホスト名のみ（ポート転送でポートが食い違い得るため）。別のホスト名で開く場合は
`SEEKX_ALLOWED_HOSTS` に追加してください。

この 2 つは LAN 上の第三者からの直接アクセスを防ぐものではありません（ブラウザを
経由しない攻撃者には効きません）。上に書いた「公開ネットワークでは起動しない」という
前提は変わりません。

### 入力値の検証（フォロワー取得）

上の 2 つがヘッダでリクエストを受け付けるかを決めるのに対し、こちらはクエリの値を検証します。
フォロワー取得の画面（`GET /followers`）はユーザー名・ユーザー ID・ページングトークン・1 ページの人数を
URL のクエリで受け取るので、利用者が自由に書き換えられます。そこで **API を呼ぶ前に
`internal/query/followers.go` で検証し、違反なら API を呼ばずに 400 でフォームへ戻します**（課金なし）。

| 値 | 許可する形式 |
| --- | --- |
| ユーザー名 | `^[A-Za-z0-9_]{1,15}$`（先頭の `@` / `＠` を 1 つだけ除いた後） |
| ユーザー ID | `^[0-9]{1,19}$` |
| `pagination_token` | `^[A-Za-z0-9_-]{16,256}$`（空なら最初のページ） |
| 1 ページの人数 | 1〜1,000 の整数 |

ユーザー名は見積りでは必須です。取得では無くてもよく（取得は ID で行い、ユーザー名は見出し・リンク・
CSV のファイル名にだけ使うため）、あるときだけ形式を確かめます。

ここまで絞るのは、どの値も送り先にそのまま埋め込まれるか、課金に効くためです。

- ユーザー名と ID は API のパス（`/users/by/username/{username}`・`/users/{id}/followers`）に、
  ユーザー名・ID・トークンはフィクスチャのファイル名にも埋め込みます。`/` `.` `%` 空白などを通すと、
  別のパスやファイルを指し得ます。
- 人数とトークンは課金に効くパラメータです。読めない人数は既定値に置き換えずに弾きます（置き換えると、
  指定と違う人数を取得して課金することになるため）。
- ID の 19 桁は、64 ビット符号付き整数の最大値の桁数です。トークンの最短 16 文字は API の定義
  （OpenAPI の `minLength`）で、最長 256 文字は URL に載せる値として打ち切る長さです。

`internal/xapi` も、パスに埋めるユーザー名（英数字と `_`）と ID（数字）を送る前に確かめ、違反なら HTTP を
送りません。フィクスチャモードでは、ファイル名にする直前にトークン（英数字と `_` `-`）も確かめます。
呼び出し側の検証を経ずに渡った値でも、別のパスやファイルを指さないための防御です。

## XSS 対策

seekx は X API から取得した信頼できない文字列（本文・表示名・alt テキスト・メディア URL、
フォロワー取得では自己紹介・場所・Web サイトの URL）を描画します。

プロフィールの Web サイトの URL は、`http://` か `https://` で始まるものだけを残して他は捨てます
（`internal/view/users.go`）。`html/template` も `javascript:` などの危険なスキームを `#ZgotmplZ` に
置き換えますが、それではカードに壊れたリンクが出るうえ、テンプレートを通らない CSV には効かないためです。

**一次防御は `html/template` の文脈依存自動エスケープです。** `template.HTML` / `template.JS` /
`template.URL` による迂回はコードベースに 1 箇所もありません。JS 側も `innerHTML` などの、文字列を
HTML として解釈するシンクを持ちません（値は `textContent` や `setAttribute` などで設定します。`csv.js` が
保存のために作る `<a>` に設定するのも、`URL.createObjectURL` が返す Blob URL とファイル名だけです）。

**二次防御として CSP ヘッダを付けています。** 全レスポンス（`/static/` を含む）に付与されます。

```
default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline';
img-src 'self' https://pbs.twimg.com https://abs.twimg.com; media-src 'self' https://video.twimg.com;
form-action 'self'; base-uri 'none'; frame-ancestors 'none'; connect-src 'none'
```

`img-src` の `https://abs.twimg.com` は、プロフィール画像を設定していないユーザーの既定の画像の配信元です
（実測済み）。許可しないと、そのユーザーのアイコンだけが CSP に止められて欠けます。フォロワー一覧で
頻出するほか、検索結果の投稿者にも当てはまります。

これは**「スクリプトについては厳格な CSP」であり、厳格な CSP ではありません。**
`style-src` に `'unsafe-inline'` が必要な理由は、項目ごとに値が変わるインライン `style` 属性が
2 箇所あるためです（`estimate.html` のバー幅、`_media.html` の `aspect-ratio`）。
どちらも CSS クラスには追い出せず、**nonce は `<style>` 要素にしか効かず `style` 属性には
適用されません**。スタイル注入はスクリプト注入より影響が小さいため、この妥協を受け入れています。

CSP が実際に守るのは、**将来の変更が API 由来の値を `template.HTML` に通してエスケープを
失った場合**です。そのとき実行そのものを止めます。

あわせて `X-Content-Type-Options: nosniff` と `Referrer-Policy: no-referrer` を設定しています。
後者は現時点の漏洩を止めるものではありません（最近のブラウザの既定
`strict-origin-when-cross-origin` でも、`pbs.twimg.com` / `abs.twimg.com` への画像リクエストに
検索語やユーザー名を含むクエリ文字列は乗りません）。既定に依存しなくなるという意味での固めです。

**`nosniff` と `.js` の MIME タイプは連動しています。** `.js` が
`Content-Type: text/javascript` で配信されないと、`nosniff` によりブラウザがスクリプトの
実行を拒否します。`TestJavaScriptContentType` で固定しています。

JS は `static/js/boot.js`（`<head>` で同期読み込み。列数を最初のペイントより前に当てるため
`defer` / `async` は不可）、`static/js/app.js` と `static/js/csv.js`（本文の末尾で、この順に読み込み。
`csv.js` はフォロワー一覧の CSV 保存）の 3 ファイルです。`csv.js` は埋め込み済みの CSV を `Blob` と
`a[download]` でファイルにするだけで、通信しません（`connect-src 'none'` と一致します）。
外部 CDN は使わず、`<script src>` は `/static/` 配下のみに限定しています。テンプレートの `<script` は
この 3 本と、下の CSV のデータブロック 1 本だけです（本数は `TestInlineScriptInvariants`、読み込む位置は
`TestLayoutLoadsExternalScripts` が固定）。

### CSV 保存

フォロワー一覧の「このページを CSV で保存」は、**表示中のページの CSV をサーバが作って HTML に埋め込み、
ブラウザがそれをファイルとして保存します。** 保存の操作では API もサーバも呼ばないので追加のコストは
無く、サーバには何も残りません（CSV は描画のたびに作って捨てます）。保存したファイルは利用者の
ディスクに残り、その扱いは利用者の責任です（[README](../README.md#安全に使うための注意)）。

**整形はサーバの純粋関数（`internal/view/csv.go` の `FollowersCSVFile`）で行います。** BOM・クォート・
無害化を Go のテストで固定でき、JS を最小に保つ方針にも合うためです。

- 先頭に UTF-8 の BOM を付けます。無いと Excel が UTF-8 と判定せず、日本語が文字化けします。
- クォートは RFC 4180 に従います（`encoding/csv`）。行の区切りもセル内の改行も CRLF です。
- **`=` `+` `-` `@` タブ CR で始まるセルには、先頭に `'` を付けます**（CSV インジェクション対策。対象は
  OWASP の推奨と同じ）。表示名・自己紹介・場所は誰でも書けるので、`=HYPERLINK(...)` のような値が、
  CSV を開いた人の表計算ソフトで数式として動かないようにします。画面のカードには元の値をそのまま出します。
- ファイル名は `followers_<ユーザー名>_<日時>.csv` です（ユーザー名が無いページでは ID）。どちらも URL から
  来る値なので、ASCII の英数字と `_` 以外を落とします。

**埋め込み先は `<script type="application/json" id="csv-data">` です。** `html/template` は
`application/json` の `<script>` の中を JS の文脈として扱い、値を JSON にして `<` `>` `&` を `\u003c` などの
Unicode エスケープに置き換えます。表示名や自己紹介に `</script>` が含まれていても、要素から抜け出せません。
一方ブラウザは、`type` が JavaScript の MIME タイプでない `<script>` を実行しないデータブロックとして
扱うので、CSP の `script-src` の対象にもなりません。`template.JS` などで包まないので、上に書いた
「迂回は 1 箇所もない」も変わりません。`data-*` 属性に入れないのは、ブラウザが HTML を読むときに
属性値の CR を LF に直し、CSV の改行が変わるためです（実測済み）。

保存は、`csv.js` が埋め込まれた CSV を加工せずに `Blob` にし、`a[download]` で保存させるだけです。JS が
無効なときは保存のボタンが出ません（ボタンの `hidden` を外すのが `csv.js` のため）。

`TestFollowersCSVDataBlock`（エスケープと埋め込んだ中身）と、`TestFollowersCSVFile`・`TestNeutralizeCell`
（整形と無害化）が固定しています。
