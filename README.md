# seekx

「X」（旧 Twitter）の投稿を、**日時・アカウント・リプライ・画像付き**などの条件で検索して
見やすく表示する、ローカル専用のツールです。特定アカウントのフォロワー一覧の取得（表示中の
ページを CSV で保存）もできます。X API v2 を直接叩きます。

**X API は従量課金です**（投稿 1 件の取得で $0.005、ユーザー 1 人で $0.010）。seekx は課金される
操作すべてに金額を表示し、実行前に件数・人数を見積れるようにしています。取得したデータは永続化しません。

## インストール

macOS / Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/shutx-net/seekx/main/install.sh | sh
```

`$HOME/.local/bin` に置きます。**sudo は要りません。** checksum（`checksums.txt`）は
スクリプトが自動で検証します。

```sh
# 置き場所やバージョンを指定する
curl -fsSL https://raw.githubusercontent.com/shutx-net/seekx/main/install.sh | sh -s -- --dir /usr/local/bin
curl -fsSL https://raw.githubusercontent.com/shutx-net/seekx/main/install.sh | sh -s -- --version v0.1.0
```

Windows（PowerShell）:

```powershell
$version = (Invoke-RestMethod https://api.github.com/repos/shutx-net/seekx/releases/latest).tag_name
Invoke-WebRequest "https://github.com/shutx-net/seekx/releases/download/$version/seekx_${version}_windows_amd64.zip" -OutFile seekx.zip
Expand-Archive seekx.zip -DestinationPath . -Force
.\seekx.exe --version
```

手動ダウンロード：  

**→ [最新リリース](https://github.com/shutx-net/seekx/releases/latest)**

`checksums.txt` を同じリリースから落とせば手で検証できます。

```sh
file=seekx_v0.1.0_linux_amd64.tar.gz          # 落としたファイル名
grep "$file" checksums.txt | sha256sum -c -   # macOS は shasum -a 256 -c -
```

## 起動

```sh
./seekx        # http://localhost:5050
```

起動したら `http://localhost:5050/settings` で Bearer Token を入力してください。

**課金ゼロで画面だけ見る**場合はフィクスチャモードで起動します（API を叩きません）。

```sh
SEEKX_FIXTURE_DIR=testdata ./seekx
```

ソースから動かす場合（devcontainer / docker / ホスト）は [DEVELOPERS.md](DEVELOPERS.md) にあります。

## 使い方

1. フォームに検索条件を入力します。
2. **「件数を見積る（$0.005）」** で総件数・時系列・予想コストを確認します。
3. **「この条件で検索する」** で投稿を取得します（**ここで初めて post read が課金されます**）。
4. ページングリンクには必ず金額が表示されます。

### 留意点

- 既定でクエリに `-is:retweet` が付きます。外すと結果の 7〜9 割がリポストで埋まり、同じ内容に
  post read を浪費します（実測値）。必要なら「リポストを含める」で外せます。

### フォロワーを取得する

1. 画面ヘッダの **「フォロワー取得」** を開き、ユーザー名（先頭の `@` は省略可）と 1 ページの人数
   （10 / 100 / 500 / 1,000 人。既定は 100 人）を選びます。以下のボタンの表示は 100 人のときの例です。
2. **「フォロワー数を見積る（$0.010）」** で、フォロワー数・全件の予想コスト・ページ数を確認します
   （対象アカウントの情報を、ユーザー 1 人分として取得します）。鍵アカウントには警告が出ます。
   フォロワーが 0 人なら取得のボタンは出ず、フォロワー数が分からないときは全件の予想コストを「不明」と出します。
3. **「最初の 100 人を取得する（最大 $1.00）」** でフォロワーを取得します。ボタンの金額は 1 ページの
   人数ぶんの最大額で、課金は返った人数ぶんです。
4. 続きは **「次の 100 人を取得（+$1.00）」** で 1 ページずつ取得します。前のページに戻る
   「前の 100 人を取得」も取り直しなので、同じく金額が出ます。**全件の一括取得はありません。**
5. **「このページを CSV で保存」** で、表示中のページのフォロワーを CSV ファイルに保存します。
   API を呼ばないので**追加のコストはかかりません。**

CSV について:

- BOM 付き UTF-8 です（Excel で開いても文字化けしません）。1 人 1 行で、ユーザー ID・ユーザー名・表示名・
  自己紹介・場所・Web サイト・フォロワー数などを書き出します（数が分からないユーザーは空欄）。
- 数式として解釈され得るセル（`=` `+` `-` `@` などで始まるもの）は、先頭に `'` を付けて無害化します。
- ファイル名は `followers_<ユーザー名>_<YYYYMMDD-HHMMSS>.csv` です（日時は表示タイムゾーン）。

## 画面

- 結果ページは 2 カラムです。左のサイドバーに**操作**（列数の切り替え・絞り込み）と情報、
  右は投稿カードだけを置いています。サイドバーは上から**「注意 → 操作 → 参照」**の順で、
  よく触るものほど上にあります。
- 表示は **1 / 2 / 3 列**を切り替えられます。選択はブラウザに保存され、**切り替えても再検索は
  起きません**。列数を変えてもサイドバーの位置は動きません。画面が狭いときは自動的に列数を減らします。
- 取得済みの投稿を**絞り込めます**（文字数・メディア数・いいね数・種別）。API を呼ばないので
  追加のコストはかかりませんが、**絞り込んでもコストは下がりません**（取得した時点で課金済みです）。
  効くのは表示中のページ内だけで、ページを移動すると解除されます。
- **フォロワー一覧も同じ 2 カラム**です。右はユーザーカードだけで、サイドバーの操作は列数の切り替えと
  **「このページを CSV で保存」** です（絞り込みはありません。列数の選択は投稿の結果ページと共通です）。
  金額が発生するリンク（「次の 100 人を取得（+$1.00）」などのページングと再見積り）は、誤クリックを
  避けるためサイドバーではなくカード列に置いています。
- 列数の切り替えと CSV 保存はブラウザの JavaScript で動きます。**JavaScript が無効だと CSV 保存の
  ボタンは出ません**（列数の切り替えも出ません。一覧と、対象・人数・コストの表示は出ます）。

## コスト

| 操作 | コスト |
| --- | --- |
| 投稿の取得 | $0.005 / 件（`max_results=10` なら $0.05、100 なら $0.50） |
| counts（直近 7 日） | $0.005 / リクエスト |
| counts（全期間） | $0.010 / リクエスト |
| ユーザー検索（フォロワーの見積り） | $0.010 / 人（見積り 1 回で 1 人分） |
| フォロワーの取得 | $0.010 / 人（100 人で $1.00、1,000 人で $10.00） |
| HTTP 400 / 429 | 課金なし |

- **まずフィクスチャモードで画面を確認してください**（完全に無料です）。
- 実検索は `max_results=10`（$0.05）から始めてください。条件を試す段階では counts の見積り
  （$0.005）が最も安い偵察手段です。
- **全ページが GET です。ブラウザのリロードや「戻る」で再検索・再取得が走ります**（フォロワーの
  見積りと一覧も同じです）。画面ヘッダのセッション累計コストを常に確認してください。
- 同じ検索の再実行は、24 時間 UTC 窓のサーバ側重複排除により追加の金銭コストが発生しにくい
  ですが、月次 cap とレートリミットは消費します。
- 月次 cap（既定 2,000,000 post reads）の 80% で警告、95% で投稿検索の実行を停止します
  （フォロワー取得は post reads を消費しないため止めません）。

フォロワー取得について:

- 課金は返ったユーザーの人数ぶんです。取得のボタンとページングに出す金額は、1 ページの人数ぶんの最大額です。
- 全件の取得は人数に比例します。**フォロワー 1 万人なら約 $100** です（見積り画面に全件の予想コストが出ます）。
- App-only の Bearer Token を使うため、**自分のアカウントのフォロワーでも Owned Reads（$0.001）は適用されません。**
- 同じ UTC 日に同じユーザーを取得し直した分は、重複排除で課金されにくくなります。ただしソフト保証なので、
  画面の金額とセッション累計はこれを考慮しない上限側の値です。レートリミットは消費します。
- ユーザーが返らなかった場合（存在しないユーザー、取得できなかった鍵アカウント）は専用の画面になり、
  課金されない見込みです。

## 安全に使うための注意

- **公開ネットワークでは起動しないでください。** seekx は認証を持ちません。到達できる相手は
  誰でも課金操作を実行できます。既定でループバックにバインドするのはこのためです。
- コンテナで動かす場合は `SEEKX_BIND=0.0.0.0` が必要で、ネットワーク構成次第では LAN の
  他の端末から画面に到達できます。
- **トークンは設定画面から入力すればディスクに一切残りません。** 画面・ログ・URL にも
  出力しません（マスク表示のみ）。
- 取得したデータは永続化しません（プロセスメモリのみ）。データベースもキャッシュも検索履歴も
  持ちません。
- **CSV に保存したデータは、あなたのディスクに残ります。** 上の「永続化しません」の外側です。
  保存した CSV の扱い（共有・再配布を含む）と、X 上で削除・更新されたデータへの追従は利用者の責任です。

仕組みと判断の理由は [docs/security.md](docs/security.md) にあります。

## 制限

X の表示要件に対して、次の 4 点が未対応です。

- 本文中の `@mention` / ハッシュタグ / URL をリンク化していません（本文は未加工で表示します）。
- 編集済み投稿の編集履歴を表示しません。
- リポストを表示する際、リポストした人を明示しません（「リポスト」バッジのみ）。
- フォロワーの自己紹介文中の `@mention` / ハッシュタグ / URL をリンク化していません（自己紹介は未加工で表示します）。

対応状況の全体は [docs/display-requirements.md](docs/display-requirements.md) にあります。

フォロワー取得には次の制限があります。

- **鍵アカウントのフォロワーは取得できない見込みです**（App-only の Bearer Token を使うため）。
  見積りで警告し、取得できなかったときは専用のエラー画面を出します（ユーザーが返らないため、課金されない見込みです）。
- 1 ページずつの取得です。全件をまとめて取得する機能はありません。
- CSV に保存できるのは表示中のページだけです（複数のページをまとめた CSV は作れません）。
